# Full-suite test harness

`npm test` is the one complete suite. `scripts/run-tests.mjs` recursively enumerates every `test/**/*.test.ts` file (including top-level test files), sorts the list, verifies exact once-only coverage, and runs the ordinary files with Node's explicit `--test-concurrency=2`. It then runs `brahms-engraving`, `janko-linter`, `janko-prepared-hmr`, and `semantic-hand` each alone, in that order. These four files are excluded from the ordinary batch, not skipped. A child failure stops subsequent phases; each completed phase prints Node's native test results and a failure includes its phase, files, elapsed time, exit status, signal, error (including timeout/buffer errors), and bounded stdout/stderr excerpt. A test's own wall/CPU assertion is a test failure, not a launcher timeout or a reason to raise the budget. The focused `test/test-harness.test.ts` checks discovery against an independent filesystem walk and checks invalid plans without running the full suite.

Use the installed lockfile dependencies (including `tsx` and Vite) with the repository's Node environment (verified on Node v26.7.0); run in an isolated worktree with no competing full suites. Integration tests may require the existing Poppler (`pdftotext`, `pdfinfo`, `pdfunite`), LilyPond and `rsvg-convert` PDF tools. Avoid running another expensive suite or editing watched inputs concurrently. For the complete gate, the CI/workflow broad budget is 900 seconds; a killed broad job is not a passing suite. A nonzero test child reports the first failing phase and its native test diagnostics, while a test speed assertion identifies its own budget and measured result. The generator probe keeps its independent 120-second timeout and reports its own process error/signal/streams if it fails. Follow a clean full gate with `npm run lint:engraving -- --strict` and `npm run build` before landing.

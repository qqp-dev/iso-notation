# Test feedback and explicit complete validation

`npm test` runs a declared inexpensive contract profile, currently seven files: pitch, grid, phonetics, notation variations, launcher contracts, public-release contracts and Reference-reader interactions. It prints **focused fast contracts**, the selected/discovered file counts and the actual results. This is bounded feedback, not a complete regression pass. On the measured Node v26.7.0 checkout, 64 checks passed in 2.30 seconds at the reconciled delivery base; see [the scoped report](reports/test-feedback-scope.md) for conditions and limitations.

```bash
npm test
npm run test:focused -- test/public-release.test.ts test/janko-reference-reader.test.ts
npm run test:focused -- test/janko-round46.test.ts --name-pattern 'Page-loop ownership:'
npm run test:full
node scripts/run-tests.mjs --full --list
npm run test:release -- --base <actual-before-commit> --head <actual-head-commit> --list
```

Explicit files must exist in recursive `test/**/*.test.ts` discovery and may appear only once. Unknown modes, incompatible arguments, empty file selections, invalid name patterns and missing release references fail without launching anything. `--name-pattern` is supported only with explicit files. A pattern that exercises no named case fails; a passing empty file is not accepted as case evidence. `--list` emits JSON without starting a child.

The full command discovers every test file recursively (133 at delivery review), compares exact scheduling coverage, runs ordinary files with Node's existing concurrency of two, then runs `brahms-engraving`, `janko-linter`, `janko-prepared-hmr` and `semantic-hand` alone in their existing order. None of those files is deleted or skipped from the complete plan. Historical fixtures now live in registration-free `test/support/round37/38/39/41-fixtures.ts`; importing their data no longer repeats their owners' tests. Independent cold-generation, changed-state, saved-history and standalone-versus-precomputed cases remain available.

Choose full validation deliberately when broad behavioral risk cannot be adequately covered by focused checks: a shared pitch/timing/model/layout or import rewrite, or unexplained regressions across unrelated scores. A mechanical refactor, filename count, homepage picker, typography adjustment or isolated source correction does not automatically justify a full sweep. Review actual coupling, select meaningful affected checks and widen coverage when evidence requires it. An implementation-check gap needs an explicit decision, not a silently green unrelated profile.

## Release coverage

Pages compares the actual pushed `github.event.before` and `github.sha`, with full Git history available. It does not infer a range from the last merge commit or silently substitute `HEAD^`. A manual focused publication requires its actual before commit. Missing/unavailable references and initial all-zero before values fail with an actionable scope request.

`scripts/test-selection.mjs` declares related contracts for UI/reader, runtime dependencies, compiler/bundler configuration, source/model, engraving, studio, publication/PDF, practice and research tooling. The plan unions mixed changes, lists coverage for every path, includes both renamed endpoints/deletions (`--no-renames`), accounts explicitly for documentation, and follows literal test-helper imports to their transitive consumers. No14/No30/No43 source changes include their own import/repeat contracts; shared source/model changes include the broader declared import cohort. The anchor solver, relative/gesture reading, written projection, current No14 publication and published Source comparison also have explicit contracts for their newer seams. Pure anchor/comparison checks require no score tools; reading/projection receive canonical lint, while publication also provisions its PDF tools. This is declared related coverage, not an assertion of perfect inferred dependency closure. An unmapped path fails with the path and the available reviewed focused/full choices. There is no implicit full fallback.

This one reviewed fixture/import and page-helper correction has representative historical checks recorded in `scripts/test-feedback-scope.json`. They apply only when **every original and final file byte identity** matches the manifest across the actual before/head Git range. A later edit to any covered fixture or test body removes those filters, selecting affected files unfiltered. Any product/runtime/source area also disables representative test-only filters, including a mixed source/historical-file change whose cohorts otherwise differ. The manifest is a bounded receipt for this transformation, not a permanent policy that those historical files need only selected cases. Every original case remains in `test:full`.

Ordinary publication runs the reported release plan, the existing data-provenance/PDF admission gate, and the configured production build. Selected score/PDF contracts provision the real LilyPond, Poppler and SVG tools; selected engraving coupling also requires strict canonical engraving lint. UI-only and runner-only checks do not require system score tools or expensive historical generation. Package dependencies/lockfile and compiler/Vite changes receive distinct runtime/build contracts rather than only runner checks. Actual before/head package content distinguishes dependency changes from test-command-only changes; altered build scripts receive compiler/build checks. Build remains required. GitHub's explicit `workflow_dispatch` **full** choice runs complete validation, strict lint and build as a standalone job; it does not deploy Pages or become a prerequisite for an ordinary focused publication.

## Progress and failures

The launcher streams Node's native TAP output as it arrives and prints elapsed phase progress every 15 seconds while a child remains pending. Node itself can serialize output within a file; the heartbeat remains visible during that silence. Neither output nor a heartbeat is a passing receipt. Completed phases report elapsed time. A nonzero exit, child interruption or spawn error stops later phases and reports phase, files, elapsed time, status, signal/error and bounded first/last stream excerpts. Launcher interrupts are forwarded only to the owned child. There is no enforced blanket 900-second launcher budget; test-specific time/CPU assertions and generator timeouts remain unchanged.

Use installed lockfile dependencies and the configured Node environment (Node22 in CI; Node26.7.0 for these local measurements). Complete/selected integration checks may require existing LilyPond, Poppler and `rsvg-convert` tools. Avoid competing expensive runs while measuring; do not raise concurrency or weaken budgets to disguise a failure. The launcher contracts exercise small disposable children, discovery against an independent filesystem oracle, invalid/mixed/renamed/deleted selections, future-edit scope invalidation, real failures and visible progress without launching the broad suite.

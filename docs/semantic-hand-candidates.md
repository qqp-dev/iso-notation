# Candidate-only semantic hand edits (slice 1)

Use the **existing real prepared studio** at `http://100.102.70.49:5175/janko.html#candidates` once this checkout is separately served and verified there (the current main server may not serve this unlanded feature). For the source-linked id17 edit the candidate shows mm. 1–4 and 9–12; an id436 edit at tick 6000 shows mm. 29–32. Compare with the unchanged `http://100.102.70.49:5175/janko.html#reference`. An isolated dev-port test is diagnostic only, not an alternate review URL. Start the existing dev server with `npm run dev`. Neither this service nor its CLI changes Reference, the canonical hand table, source fixtures, MIDI, or PDF. No server/browser is needed to save a revision; without a matching prepared generation, the CLI explicitly returns `pending`, not `ready`.

```sh
node --import tsx scripts/semantic-hand.ts status
```

On a clean start, `status.revision` equals `status.baseline`; after an edit it is the current editable head. Copy `revision` from a **current** status as `base` (the tool supplies source/model/engine identity internally). A stale status has no editable `revision`; use its `baseline` only for an explicit `recover` request below. Save this request as a JSON file **outside the checkout**, or pipe the JSON into `change`:

```json
{"schema":1,"score":"brahms-op118-no1","base":"<revision from status>","intent":"assign-hand","target":"LH","scope":"source-linked","selected":[{"id":"brahms-op118-no1-17","pitchClass":0,"octave":4,"tick":240,"expectedHand":"RH"}],"reason":"Candidate reading for review"}
```

```sh
node --import tsx scripts/semantic-hand.ts change --json /path/to/request.json
node --import tsx scripts/semantic-hand.ts explain --revision <saved-revision>
# undo the current head only; it appends a new revision, preserving the record
printf '{"base":"<saved-revision>","revision":"<saved-revision>"}' | node --import tsx scripts/semantic-hand.ts undo
```

If `status` reports `state: "stale"`, the saved revision is **not replayed**. The Candidates view shows a STALE/not-applied diagnostic naming the saved/current identity and the source/engine mismatch; Reference is still generated canonically. `change`, `explain`, and `undo` reject the stale state. To deliberately start a new candidate on the **watched default path**, inspect the diagnostic and source evidence, copy the new `baseline` from `status`, update only the request's `base` and guards for the current source, then run:

```sh
node --import tsx scripts/semantic-hand.ts status
node --import tsx scripts/semantic-hand.ts recover --json /path/to/new-guarded-request.json
node --import tsx scripts/semantic-hand.ts explain --revision <new-revision>
```

`recover` only accepts a stale saved state and a valid, effect-checked new assignment. It preflights the entire guarded request before touching the state, atomically moves the original bytes to `.semantic-candidate.local.archive-<time>-<hash>` (ignored by Git), then writes a new append-only state with a new revision. Its response returns the archive path and byte SHA-256. It will not auto-rebase the old intent or discard old history. If publication fails, the CLI says `pending`; check the exact revision in prepared status after the watcher finishes. Never use an alternate `--state` as a substitute for recovery on the default watched path. A legacy history without per-component fingerprints reports the saved/current identity and an undifferentiated source/base/engine mismatch; archive rather than guessing which component changed.

`--wait-ms 0` saves without waiting for the live dev-server status; by default the CLI waits up to 5s and polls the prepared status endpoint. If a regeneration is still running, run `explain`, then observe the candidate revision in the prepared status line and the candidate card. `--server` overrides the server URL; `--state` overrides the ignored state file for isolated tooling/tests (the live studio only watches the default). Unsupported commands (including `promote`) fail with a diagnostic. Selection must use exact revision-local event ids and pitch/tick/old-hand guards: `this` selects the guarded event, `set` selects an explicit array, and `source-linked` resolves a single guarded statement through the pinned provenance sidecar. A source-linked selection rejects ambiguous unisons, multiple source contributors, collisions, missing or mismatched occurrences, or altered source/model/engine fingerprints. A repeated request must carry the current head and current old-hand guard; if it results in an identical projection it returns `replay: true` without appending history. Do not use a source line/column as a universal event ID: linkage is scoped to the pinned fixture/source identity, source voice and statement plus a fully guarded performed occurrence. A crash leaving `.semantic-candidate.local.lock` requires manual investigation before removing the lock; never automatically discard an in-flight writer.

The state `.semantic-candidate.local` and its byte-preserved `.archive-*` histories are ignored by Git, versioned, atomic-renamed, history-hashed and in the Vite watcher/fingerprint. Tests use isolated state paths and never clear an operator's saved default state. The watcher marks previous candidate output stale and publishes the matching prepared generation by HMR, preserving viewer zoom/tab/scroll; build output intentionally ignores local edits. The default studio without saved state keeps the existing three Round 49 cards. Candidate score projection overrides only the additional `semantic-hand` card's Brahms score; the canonical Reference entry is not rewritten. Saved-state identity includes the pinned authored source, duration fixtures/provenance and engine/editorial code; drift fails closed rather than silently rebasing a revision. The production score builder and canonical correction table remain the legacy baseline until a separately approved migration/promotion slice.

`reviewWindows` are whole-system crop coordinates derived from changed systems and guarded events in the active candidate projection, sorted by score position. The CLI `changedCrops` and `unchangedCrops` compare precisely those rendered windows against the immediately preceding candidate revision (not against Reference); an unchanged crop can still carry an earlier edit. All active edited regions remain visible after subsequent edits. Windows are stored in the fingerprinted record and reused by the prepared generator; no sample-only or duplicate viewer route exists. `effects` counts and owner diffs come from real layout plans (rests, beams, clasps, tie-origin suppressions and painted long-duration mark owner IDs), real crossing detection, SVG system/page/crop byte comparisons and the real linter. `NO_VISIBLE_EFFECT` is reported if no page changes. Tie/duration owner changes are reported as exact added/removed mark identities, not inferred from equal counts or option badges. Candidate windows use canonical Brahms options, not the Round 49 exploratory options; option badges on older cards are not evidence of this candidate's changed geometry. Round 49's historical A/B/C copy is not a label for the new candidate.

Sunset once a separately judged unified semantic score authority replaces the legacy table, not in this slice. Promotion, generalized scene IR, duration policy, expression painting and source re-import are intentionally unsupported.
- Full release gate: `npm test`, `npm run lint:engraving --strict`, `npm run build`. A local edit/preview is **not** a release; the PDF freshness test and source export/compiler tests remain part of the official suite. The CLI's measured `resolve`, `deriveLayoutLint`, `publicationWait` and `commandTotal` and the server-reported `publication.generationMs` distinguish full real-engine generation from watcher/poll overhead; browser rendering/acceptance is a separate operator observation, never inferred from a ready status.

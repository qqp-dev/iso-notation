# Guarded duration-mark comparisons (candidate-only)

The existing `scripts/semantic-hand.ts` CLI and `.semantic-candidate.local` transaction/history are reused; no authored score, canonical option, formal round metadata, MIDI, PDF, or Reference view is edited. The only formal round-opening authority remains `src/render/janko/candidates.ts` (Round 50 GOLD remains unchanged). Runtime cards in Candidates are guarded comparison data, not promotion.

Use an isolated `--state /path/to/private-candidate.json` with an isolated server configured to watch **that same state** for demonstrations. Never aim an alternative state at the operator's server. On the live service, activation of a new candidate state belongs to the architect after preservation of prior history and conflict review.

1. `node --import tsx scripts/semantic-hand.ts status --score brahms-op118-no1 --state <file>` returns the guarded `revision`, per-variant revision/lint/seat refusals and windows. Use `--score bach-goldberg-var1` for Bach. The old hand `assign-hand` request and its legacy state/history remain supported.
2. `node --import tsx scripts/semantic-hand.ts inspect-duration --score brahms-op118-no1 --measure 9 --tick 1584 --state <file>` returns the **complete sorted** shared owner IDs, family, mount, semantic anchor, bounded mark ink, local knockout/edge clearances, obstacles and explicit uncertainty. Inspection reads the saved hand-projected candidate at the guarded revision, not the canonical ownership when a hand assignment has changed it. A bracket's ink box is the conservative whole-bracket union, not a fictitious isolated outline. Neither this inspection nor the partial ink scene certifies global free space. Brahms m. 1 t48 has half-ring bracket owners #4/#6, plus independent 192 #5; m. 2 t240 has #15~c1's dotted 144 horizontal half carrier (not a bracket, not a 192 full ring); m. 5 t816 has half bracket #48/#49/#50; m. 9 t1584 has the shared 192 ring #117/#118.
3. Submit a JSON `change` with `schema:1`, `intent:"engrave-duration"`, exact `score`, **fresh** `base` from status, unique `variantId`, bounded `windows`, and optionally `tokens`, `options` or `placements`. Pass `--json <file>`, `--state <file>`, `--score <score>` and `--server <matching isolated server URL>`; `--wait-ms 0` returns after saving rather than falsely claiming browser readiness. Accepted rule-wide keys are `tokens.halfRingGap` (0–2pt), `tokens.detachedSymbolAir` and `tokens.horizontalMountAir` (0–3pt), and `options.exceptionCarrier` (`horizontal` or `symbol`). No duration, musical facts, arbitrary positions, or other option names may be supplied. An occurrence preference instead has the form:

```json
{"target":{"score":"brahms-op118-no1","measure":9,"tick":1584,"family":"ring","ownerIds":["brahms-op118-no1-117","brahms-op118-no1-118"]},"preference":"beside"}
```

`"above"` keeps the existing horizontal shared carrier; `"beside"` asks the shared detached symbol seat to fit using the engine's actual ink/knockouts. The request is **not** an x/y override. A fit refusal publishes its reason and keeps the existing horizontal duration statement; never call that an honored beside seat. The m. 9 literal fits, preserves both owners and 192 value. `options.exceptionCarrier:"symbol"` is rule-wide, unlike the targeted preference. It cannot be combined with any targeted seat preference: on fit refusal the detached rule could split a shared statement rather than honor the horizontal fallback, so the guarded transaction rejects the combination atomically. Inspect the new variant's mark in the Candidates SVG and its per-variant lint/refusals; BRONZE's pre-existing folding findings are not concealed as candidate success and only **new** hard violations block a variant. No claim of complete collision-free geometry is made.
4. Build the comparison *as data*, changing `base` after each append. For example four variants with one score: `current` (no controls, windows mm. 1–2 and 5–8), `gap-small` (`halfRingGap:0.15`, same windows), `detached` (`exceptionCarrier:"symbol"`, same windows) and `shared-seat` (`placements` as above, window mm. 9–12). To compare two gap readings, replace the same `gap-small` variant with `halfRingGap:0.35` using the current head; up to four runtime cards coexist. `explain --revision <head>` reports the changed variant, rule-wide deltas, targeted owners, windows, lint and fit refusals. `undo` with JSON `{"base":"<head>","revision":"<head>"}` appends a revision restoring the previous projected variant set; it never deletes history. Unsupported fields, wrong score, stale head/source/engine or incomplete/ambiguous owners fail before any state write.

The candidate browser marker `#janko-studio[data-prepared-observation]` only reports an **observable double-animation-frame opportunity** when the Candidates view is visible, with matching applied revision, generation, candidate artifact hash and active variant identity. Compare it with the server's nonstale status; a saved/ready result alone, hidden page, wrong view, superseded response or absent browser does not prove visible output. It is not compositor-pixel proof or operator aesthetic acceptance. The Reference artifact remains canonical, byte-identical and independently cached; unchanged variants reuse content under the complete score/variant/source/engine/font/MIDI input fingerprint.

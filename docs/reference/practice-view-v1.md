# ISO Practice rendered view · contract 1

`renderPracticeView(request)` from `src/render/janko/practice.ts` is the isolated ISO core. The local browser package (`build/practice-v1/`) exposes that same renderer as `window.IsoPractice.renderPracticeView` in a self-contained classic script. No studio, DOM, Node, npm, network or server is required at runtime. See `handoff.md` for host usage. Offline hosting is Music Box's technical integration requirement, not a license restriction. The package includes actual font license, exception and provenance notices (`notices/URW-*`); preserve these with the package. It is excluded from the Pages `dist/` and is not a Windows executable or verified WebView2 deployment. The existing studio Candidates view uses the exact renderer; Bach GOLD and Brahms BRONZE References remain unchanged.

## Inputs and outputs

```ts
renderPracticeView({ rudiment: 'scale', scaleType: 'natural-minor', tonicLinear: 48,
  width: 760, height: 380, guide: 'two-guides' }); // or scaleType: 'major'
```

- `tonicLinear` is the **absolute** linear pitch index `12 * octave + pitchClass` (`C4 = 48`), not MIDI (`MIDI = tonicLinear + 12`). A UP/DOWN request changes this index by ±1 (a 1-span). The renderer resolves everything else. Supported integer tonics: 36–60 inclusive. Exact input selection, dimensions and guide treatment are explicit; unknown rudiment/scale/guide, non-finite sizes or out-of-range tonic throw `RangeError`.
- `width` 560–1600 and `height` 360–900 are available viewport dimensions in CSS pixels, also used as SVG user coordinates; intrinsic `width`/`height` are emitted in `px` (e.g. `760px × 380px`). Preserve aspect ratio when embedding. At extreme tonics and low heights the renderer may throw if the rails cannot fit; resize and retry rather than clipping or shrinking the symbols. Default guide is `two-guides`; `none` removes only the continuous guides.
- Return: `{svg, selectionId, isoVersion, contractVersion, guide, attacks, systemCount, railClearance}`. `svg` is the **complete** SVG string, pitch-black with embedded URW Gothic Demi OTF for the real engine pitch numerals; no asset URL, global CSS or studio dependency. `selectionId` is stable `scale:<scaleType>:<tonicLinear>` (e.g. `scale:natural-minor:48` or `scale:major:48`) and intentionally does **not** encode guide or viewport. `attacks` report each index, RH absolute pitch (`pitchLinear`, retained for contract-1 clients), onset tick, real engine x, and separately owned `hands.RH` and `hands.LH` `{finger,row,y,pitchLinear}`. LH pitch is a real engraved note one 10-span below RH, not a cue-only extrapolation. Indexes/ticks align 1:1. `contractVersion = 1` identifies the input/output schema, while `isoVersion = 0.1.3` is the renderer's implementation label; neither identifies exact bytes. Use `manifest.json`'s SHA-256 `buildId` plus per-file digests for update integrity. The embedded font is sourced from the project's `public/fonts/URWGothic-Demi.otf`.
- Supported types (`SUPPORTED_PRACTICE_SCALES`): `major` (Major) and `natural-minor` (Natural minor N26). Only N26 is selected under the operator's two-thumb / 3+4 / R0-thumb / R1-R2-long-finger / same-contour-both-hands assumptions; this is not a universal ergonomic optimum. Harmonic, melodic and jazz minor remain unsupported. Two simultaneous sequences (15 sixteenth-note attacks per hand, 12 ticks each at TPB 48) have one apex. Major ascends `[0,2,4,5,7,9,11,12]`, RH `23412312`, LH `43213214`, physical rows `33324423` (even tonic) or `22213312` (odd tonic), with provisional reversed descent. N26 cycles by `[2,1,2,2,1,2,2]` in 1-spans, ascends offsets `[0,2,3,5,7,8,10,12]`, relative row contour `[2,0,1,1,1,0,2,2]` (R0/R1/R2), RH `31234123` and LH `21432132`. Degrees 2 and 6 are both R0/thumb positions. Its physical rows are that contour uniformly +1 for even tonics (`31222133`) or +2 for odd tonics (`42333244`), checked against both hands' pitch parity. N26 descent **exactly reverses** the first seven steps/fingers/rows, without another apex; the operator explicitly specified this path. Eight attacks occupy the first 96-tick measure; the second has seven. Both measures fit in one system; the real engine paints two beam levels for each hand in four-note groups 4/4/4/3 (48-tick grouping), without fabricating a final note or rest. The row is a **vertical position**, not a printed row-number string. Rows 1 and 3 accept even-class pitches; rows 2 and 4 accept odd-class pitches. Guide A (`two-guides`) is operator-selected as the consumer default; descent/no repeated apex is still provisional and not operator-approved.
- RH is always the upper rail, LH the lower, both above **one** engine-engraved pitch staff carrying actual RH and LH notes one 10-span apart. Each has four fixed row heights (row 1 lowest / nearest, row 4 highest / farthest); the two-guide treatment draws **two faint mid-row guides per hand** (four total), never through a numeral. Conventional fingers are amber sans-serif 1–5 versus white URW Gothic absolute pitch symbols. Cue `x` is taken from `layoutJankoScore`, and the staff is emitted by `renderSystem`. Palette transformation applies only to that output; white knockouts become opaque black **on the original paint layer**, preserving their protective order. No GOLD/default engine ink changes. `railClearance` is a conservative gap (SVG user units) from the lowest *possible* rail digit ink envelope to this two-hand sixteenth-note fixture's actual positioned notehead/stem/beam envelope and the engine's staff-top coordinate, with a 1-unit stroke pad. It is **not** general collision certification for future flags, ottavas or arbitrary scores; the canonical linter does not inspect these rails.

`test/janko-practice.test.ts` pins the deterministic integration fixture: tonic 48/49 RH and LH pitches (LH one 10-span below), raw fingers and parity row placements for both scales, exact N26 reverse descent, 1-span transposition, separate hand alignment, geometry clearance, two guides versus none, embedded font, one system, rejection cases, studio use of the exact renderer, and unchanged Reference. The `test/fixtures/practice-v1.json` file provides consumer-readable inputs and expected identities/arrays. No audio, playback or full-score tablature is provided.

**Consumption boundary:** Music Box owns its selector, UP/DOWN events, persistent host and inline SVG insertion. Unsupported inputs throw `RangeError` synchronously (including viewport fit failure), not fallback graphics. `selectionId` is `scale:<scaleType>:<tonicLinear>` regardless of guide/size; `resolvePracticeScale(tonicLinear)` still defaults to major. Re-render with measured CSS-pixel width/height after resize. Compilation or Linux smoke tests are **not** proof that this Windows PowerShell/WinForms host can render SVG or load the embedded font; final host acceptance belongs to Music Box, separately from this source/bundle validation.
